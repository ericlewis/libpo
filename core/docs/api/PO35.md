# PO-35 / PO-137 C API

[API overview](../C_API.md) · [Documentation](../README.md)

See [ownership and completion](../C_API.md#data-flow-and-ownership) before integrating these APIs.
Use the [shared stereo APIs](STEREO.md) to parse, build and transmit a frame.

## PO-35 Records

`po35_settings_*`, `po35_pattern_*`, `po35_speech_header_*` and
`po35_speech_record_*` provide lossless structural codecs. The nine-byte speech
header contains a slot, record count, frame rate and five raw metadata bytes.
Each speech record is 44 bytes. Group collection, ordering and completeness
checks belong to the application, not the frame parser. The transactional edit
surface below performs those checks for an edited frame; the frame parser itself
continues to expose raw packets.

The two indexed table records have additive, tag-named types:

| Type and codec prefix | Payload | Fields |
| --- | --- | --- |
| `po35_table_7be7_t`, `po35_table_7be7_*` | 9 bytes | `index`, `data_raw[8]` |
| `po35_table_1c7f_t`, `po35_table_1c7f_*` | 13 bytes | `index`, `data_raw[12]` |

Each provides `decode(data, len, out)` and `encode(value, out, capacity)` with
the same fixed-record error and ownership contracts as the other PO-35 codecs.
All index and body byte values survive roundtrips. Observed indices 0..7 are not
validation limits. Table bodies remain raw: no gain, detune, voice enum or
three-integer interpretation is implied. The types work with the tested
PO-35/137 profile; common structure does not imply identical table contents.

Existing `po35_settings_t`, `po35_pattern_t`, `po35_speech_header_t` and
`po35_speech_record_t` retain their layouts. Speech gain and unvoiced members
are raw codes with unresolved transfer functions, not dB or boolean values.
The pitch/coefficient conversion used by the speech renderer is a reconstruction
model, not an additional wire-format guarantee.

Settings contain a variable pattern chain, limited to `PO35_CHAIN_MAX_COUNT`
entries by the packet payload capacity (99 entries). The PO-35 manual describes
up to 64 chained patterns; device handling of larger encoded chains is
unverified. The record codecs preserve fields without normalizing their values.
PO-35 drum patches use `po32_patch_packet_t`
and `po32_packet_encode` / `po32_packet_decode`.

See [PO-35 format reference](../formats/PO35.md) for record offsets and unresolved fields.
The shared stereo transport does not imply shared PO-33/35 field semantics.
Other speech header metadata, exact voice/effect behavior and gain laws remain
unresolved; structural preservation does not establish model identity or
physical cross-loading compatibility.

## Indexed Table Replacement

`po35_table_1c7f_replace` replaces the existing row whose index matches a
`po35_table_1c7f_t`. Its twelve body bytes remain opaque, and all index values
are representable. The function does not interpret effect numbers, normalize
the data or implement an experimental playback model.

The source must contain exactly one complete frame, with no trailing bytes.
Every `1C7F` payload must have its fixed thirteen-byte size, the selected index
must occur exactly once, and any present speech groups must be complete.
Duplicate unrelated indices and unknown records remain preserved. Successful
replacement retains all other payloads and every packet's order, length and
offset, including original speech packet boundaries. Running checksums and
whitening are rebuilt, so later wire bytes can change even when their decoded
payloads do not.

The output has exactly `frame_len` bytes. Supply separate workspace and output
buffers of at least that size; there is no heap allocation or separate planning
call. After decoding `donor_row` and providing those buffers:

```c
size_t written = 0;
po_status_t status = po35_table_1c7f_replace(
    frame, frame_len, &donor_row, workspace, workspace_bytes,
    output, output_capacity, &written);
/* Only PO_OK makes output[0..written) a complete replacement frame. */
```

All pointers are required. The borrowed source and replacement may overlap
each other and must remain immutable during the call. Workspace, output frame
and output-length storage must be disjoint from both inputs and from each
other. Prohibited aliases and overflowing ranges return `PO_ERR_INVALID_ARG`
without writes. Other failures preserve the destination frame and clear the
valid, nonoverlapping output-length value. Workspace contents are unspecified;
successful output leaves excess capacity untouched.

| Error | Cause |
| --- | --- |
| `PO_ERR_INVALID_ARG` | Missing required pointer, prohibited alias or overflowing range |
| `PO_ERR_BUFFER_TOO_SMALL` | Workspace or output capacity below `frame_len` |
| `PO_ERR_FRAME` | Invalid framing, checksum, tail or trailing bytes |
| `PO_ERR_PARSE` | Malformed `1C7F` row, missing/duplicate selected index or incomplete speech group |

The operation validates the entire frame even after finding a malformed table
row, so a later framing error is not hidden by that row error. Byte-preserving
replacement is a software guarantee; device acceptance and the audible effect
of an isolated row remain unverified.

## Speech Control Views

`po35_speech_tone_t` names two raw fields, `pitch_raw` and `formant_raw`.
`po35_speech_controls_get_tone(controls, out)` reads them from the first two
parameter bytes of an existing `po35_speech_controls_t`.
`po35_speech_controls_set_tone(controls, tone)` writes only those two bytes,
preserving the other parameters and all four retained state bytes.

On the tested PO-35, both controls store `01` at displayed -127 and `FF` at
displayed +127. Those endpoints fit `display = code - 128`; intermediate
display values and audible scaling have not been calibrated. The helpers
preserve all 256 raw codes, including `00`, without normalization or range
restrictions based on the observed UI. They do not assign per-step semantics.

The speech header's root control is separate from normal pitch.
`po35_speech_header_get_root(header, out_root)` reads its signed big-endian
16-bit value from payload offsets 6..7 (`metadata[2..3]`).
`po35_speech_header_set_root(header, root)` writes only those two bytes and
preserves all other header fields. Displayed +2047 and -2036 matched `07 FF`
and `F8 0C` in PO-35 readbacks. Root units, pitch direction and the acoustic
transfer function remain unverified. The setter accepts every `int16_t`
value; software representation is not a device acceptance limit.

All four helpers return `PO_ERR_INVALID_ARG` for null arguments and leave
outputs unchanged on failure. Input and output storage must not overlap.
The existing public structs and raw record codecs retain their layouts and
behavior. The shared PO-35/137 grammar supports using these byte views with
either profile; the new control experiments used a PO-35, not a PO-137.

Typical edits, after decoding `settings` and `header`, are:

```c
po35_speech_tone_t tone;
if (po35_speech_controls_get_tone(&settings.speech[0], &tone) == PO_OK) {
    tone.pitch_raw = 1; /* Observed -127 endpoint; keep formant unchanged. */
    po35_speech_controls_set_tone(&settings.speech[0], &tone);
}
po35_speech_header_set_root(&header, -2036);
```

Re-encode the modified records with the existing codecs. These helpers edit
decoded objects; they do not rebuild a transfer or render the control values.

## Speech Events

`po35_speech_event_t` is a lossless view of one step's event and secondary
bytes. Its four fields are stored nibble values, each in `0..15`:

| Field | Stored location | Meaning |
| --- | --- | --- |
| `slot_raw` | Event high nibble | Speech slot selector; slots 0..14 are known |
| `code_raw` | Event low nibble | Event code, including unnamed values |
| `note_raw` | Secondary high nibble | Note code, dependent on pattern key/scale |
| `gate_raw` | Secondary low nibble | Gate-duration code; exact timing remains unresolved |

`po35_speech_event_decode(event_raw, secondary_raw, out)` accepts every byte
pair. `po35_speech_event_encode(event, out_event_raw, out_secondary_raw)` accepts
all four-bit field values and returns `PO_ERR_RANGE` if any field exceeds 15.
Both return `PO_ERR_INVALID_ARG` for null pointers and leave outputs unchanged
on failure. The encode input and both output bytes must be disjoint, including
the two outputs from each other. The helpers use no allocation or hidden state.

Named event codes are `PO35_SPEECH_EVENT_NONE` (`0`),
`PO35_SPEECH_EVENT_ONSET` (`1`) and `PO35_SPEECH_EVENT_CONTINUE` (`F`). Tested
PO-35 playback restarts the source on an onset and advances an ongoing voice
on continuation, including across pattern boundaries and note changes. After
the tested shortened gate ends the note, later continuations do not restart it.
This is not a general sequence validator or a renderer.

For example, change the first step's note while preserving its other fields:

```c
po35_speech_event_t event;
po_status_t status = po35_speech_event_decode(
    pattern.speech_events[0], pattern.speech_secondary_raw[0], &event);
if (status == PO_OK) {
    event.note_raw = 8;
    status = po35_speech_event_encode(
        &event, &pattern.speech_events[0], &pattern.speech_secondary_raw[0]);
}
```

Re-encode the pattern with `po35_pattern_encode`. The helpers change only the
two selected bytes. Parameter rows, FX state, the stored mask and all other
steps remain untouched. Inactive secondary state, slot 15 and unnamed event
codes survive roundtrips; accepting them is not a claim of device validity.
Changing a slot or event code does not automatically recompute the mask.

The step's `note_raw` is separate from the PO-35's **pattern-wide** key and
scale controls. These helpers do not edit, infer or transpose that pattern
setting. Controlled PO-35 readbacks localized key and scale edits to pattern
footer byte 177, but the numeric key encoding remains unresolved.

Existing public structs retain their layouts. Both PO-35/137 profiles share
this byte view; playback evidence comes from a PO-35. There is no note-to-MIDI,
seconds or tick conversion API because those numeric laws remain context
dependent or unresolved. See the [format reference](../formats/PO35.md).

## Pattern Key and Scale

`po35_pattern_scale_get/set` exposes the scale in the low two bits of
`pattern.tail_raw[0]` (pattern payload byte 177):

| Enum | Stored code | Scale |
| --- | ---: | --- |
| `PO35_PATTERN_SCALE_MAJOR` | 0 | Major |
| `PO35_PATTERN_SCALE_MINOR` | 1 | Minor |
| `PO35_PATTERN_SCALE_BLUES` | 2 | Blues |
| `PO35_PATTERN_SCALE_ARAB` | 3 | Arab |

Controlled PO-35 readbacks directly identify codes 0, 2 and 3. The user
confirmed Minor as the fourth option, assigning the remaining code 1. A
later readback contained code 1 after an intended Minor edit, but the
key-bearing bits also changed; an isolated Minor-only edit remains unverified.
The setter changes only those two bits, preserving the key-bearing upper bits,
unknown bit 2, other footer bytes and all step data. For example:

```c
po_status_t status = po35_pattern_scale_set(&pattern, PO35_PATTERN_SCALE_MINOR);
if (status == PO_OK)
    status = po35_pattern_encode(&pattern, encoded, sizeof(encoded));
```

Null pointers return `PO_ERR_INVALID_ARG`; invalid enum values return
`PO_ERR_RANGE`. Failures leave the pattern or output unchanged. The tested
PO-35 also changed byte 177 when PATTERN + knob A changed the key. Its exact
numeric key layout remains unresolved. A matched Major-scale readback stored
`00`, `08` and `60` for user-reported center C, C-sharp and upper +C; the
earlier reported lower -C stored `A0`. These bit-2-clear values support a
`0x08` step per semitone. Callers can preserve or copy the raw byte, but this
API does not convert note names or transpose steps.
PO-35/137 share the structural codec; this scale mapping has direct device
evidence on PO-35 only.

## Pattern Voice and FX Selection

`po35_pattern_index_pair_decode` splits one byte from
`pattern.index_pairs_raw[step]` into `po35_pattern_index_pair_t`: `fx_raw` is
the high nibble and `voice_raw` is the low nibble. The encoder combines them
without consulting the indexed voice or FX tables. Both fields retain all
raw values in 0..15, including values not observed on a device. Invalid
encode values return `PO_ERR_RANGE` without modifying the output byte.

The tested PO-35 displayed high value `3` as FX 12 and high value `7` as the
FX-16 clear selection. Pattern 15's low values `5` and `7` displayed voices
6 and 8; changing low values `0` and `4` in a matched speech-only pattern
produced a small audible contrast consistent with voices 1 and 5. Factory
Pattern 4 contains `70`, `20` and `75` at selected steps, matching the
user-observed voice 1/6 and FX 11/16 choices. This evidence does not assign
an audible law, map every raw value, or establish PO-137 playback parity.

To change only the voice choice at a step:

```c
po35_pattern_index_pair_t pair;
po_status_t status = po35_pattern_index_pair_decode(
    pattern.index_pairs_raw[step], &pair);
if (status == PO_OK) {
    pair.voice_raw = 5; /* Observed voice-6 selection on PO-35. */
    status = po35_pattern_index_pair_encode(
        &pair, &pattern.index_pairs_raw[step]);
}
```

Re-encode the pattern with `po35_pattern_encode`. The other nibble, events,
parameters, step state and stored mask remain unchanged. Input/output storage
must be disjoint, and null pointers return `PO_ERR_INVALID_ARG`.

The first byte of each `pattern.speech_parameters[step]` row has an observed
pitch role. The factory Pattern-15 sweep retained `128 -> 255 -> 128` across
the bar; a matched speech-only pattern with this byte held at `128` played
flat across all eight voices on the tested PO-35. The raw byte remains
directly accessible for edits. This observation does not establish a
semitone, cents or display conversion.

## Pattern Speech Controls

`po35_pattern_speech_controls_get/set` reads or writes the four raw speech
parameter bytes at one zero-based step in `po35_pattern_t`. The
`po35_speech_step_controls_t` fields follow storage order: `pitch_raw`,
`formant_raw`, `start_raw` and `speed_raw`. This view differs from
`po35_speech_controls_t`, which holds a recorded sound's defaults in global
settings. All byte values, including zero, survive; zero can have different
behavior on an onset and a continuation, so the setter does not normalize it.

```c
po35_speech_step_controls_t controls;
po_status_t status = po35_pattern_speech_controls_get(&pattern, step, &controls);
if (status == PO_OK) {
    controls.start_raw = 24;
    status = po35_pattern_speech_controls_set(&pattern, step, &controls);
}
```

The tested PO-35 supports the pitch and formant byte roles through controlled
playback. In a later constant-parameter Pattern-15 comparison, changing only
the third byte to `24` or the fourth to `160` appeared to produce the intended
start or speed response. The user reported display readings of `12` and
approximately `-88` respectively. Varying one parameter from steps 5..11
and returning it to baseline also appeared to work. These are one-case
qualitative reports, not display conversions or timing/rate laws.

Null pointers return `PO_ERR_INVALID_ARG` and steps outside 0..15 return
`PO_ERR_RANGE`; failures leave the output or pattern unchanged. A successful
set changes only that step's four speech bytes. Events, other steps, voice/FX
selections, retained state and the stored mask remain untouched. Re-encode
the pattern separately with `po35_pattern_encode`; the helper does not
simulate step interpolation or rebuild a transfer.

Pattern key and scale are separate from these step locks. The device applies
PATTERN-plus-knob edits to the active chain's patterns when PATTERN is
released; no numeric key/scale conversion is exposed by this API. The tested
PO-35 stored both settings at footer byte 177; see the
[format evidence](../formats/PO35.md#pattern-records).

## Transactional Speech Replacement

`po35_speech_edit_t` describes a replacement by slot, header record-rate byte,
and a borrowed contiguous body of encoded 44-byte records. It deliberately
accepts encoded records rather than WAV or PCM: record analysis is the separate
`po35_analysis.h` API, while WAV parsing, allocation and file access remain
hosted concerns. This keeps the frame transaction freestanding and lets callers
use records obtained from analysis, a device backup, or another encoder.

The transaction surface is:

```c
po_status_t po35_speech_edit_plan(
    const uint8_t *frame, size_t frame_len,
    const po35_speech_edit_t *edits, size_t edit_count,
    po35_speech_edit_plan_t *plan);

po_status_t po35_speech_edit_rebuild(
    const uint8_t *frame, size_t frame_len,
    const po35_speech_edit_t *edits, size_t edit_count,
    const po35_speech_edit_plan_t *plan,
    uint8_t *workspace, size_t workspace_bytes,
    uint8_t *out_frame, size_t out_capacity, size_t *out_frame_bytes);
```

Call `po35_speech_edit_plan` first. It validates the whole source frame and
requested slots without writing an output frame, then fills a
`po35_speech_edit_plan_t` with exact workspace and frame capacities,
`selected_slot_mask`, and `affected_slot_count`. Bit 0 of the mask is slot 0;
only the 15 speech-slot bits may be set. A successful plan has
`PO35_SPEECH_EDIT_REASON_NONE`, `failed_edit_index == SIZE_MAX` and
`failed_slot == UINT8_MAX`.

Planning itself uses no workspace. A successful plan nevertheless reserves a
staging workspace equal to `required_frame_bytes`, so rebuild can finish a
complete frame before copying it to caller output. The subsequent rebuild
revalidates the frame rather than retaining source packet state from planning.

For a rejected edit, the plan clears capacities and selected-slot fields, and
uses `reason`, `failed_edit_index`, and `failed_slot` to explain it. Reasons
distinguish duplicate and out-of-range slots, malformed record sizes or counts,
an absent slot, an incomplete group, and an unknown extension in a selected
group. `po35_speech_edit_rebuild` consumes a successful plan for the same
structural input shape, revalidates it, takes the caller-owned workspace, and
produces one complete output frame. A failed plan or one whose fresh structural
measurement differs returns `PO_ERR_INVALID_ARG`. The plan is not a content
snapshot: current header metadata, rate bytes, or record bytes may differ from
planning when they retain the same valid slot set and capacities.

For a failure unrelated to one edit, a valid plan output is the neutral
no-plan state: zero capacities, zero selected-slot fields,
`PO35_SPEECH_EDIT_REASON_NONE`, `SIZE_MAX`, and `UINT8_MAX`. A null or invalidly
aliased plan output has no result-storage guarantee.

Edit slots must be unique and less than `PO35_SPEECH_SLOT_COUNT`; a selected
slot must exist in a complete source speech group. Each nonempty record body is
a multiple of `PO35_SPEECH_RECORD_BYTES`; a zero-byte body may use a null
record pointer. The body is additionally limited to 65,535 records:
`record_bytes / PO35_SPEECH_RECORD_BYTES <= UINT16_MAX`. This is the wire
header's BE16 limit, not the hosted editor's separate 640-record creation
policy. The transaction retains unselected packets, payload boundaries and
opaque header bytes. Selected headers retain their slot and metadata bytes 4–8,
while their BE16 record count and rate byte come from the edit. An unknown
extension inside a selected group is rejected rather than silently removed.

The source frame, edit descriptors and record buffers are borrowed and may
overlap each other. A plan output or input, workspace, output frame and
output-length storage must be disjoint from one another and from all borrowed
input. Prohibited aliases return `PO_ERR_INVALID_ARG`; no output guarantee
applies to an invalid alias. Missing required pointers also return
`PO_ERR_INVALID_ARG`. Planning reports invalid slots or record bodies as
`PO_ERR_RANGE` with an edit reason, unsafe selected groups as `PO_ERR_PARSE`
with an edit reason, and invalid wire framing as `PO_ERR_FRAME`. Rebuild maps a
newly invalid source or edit request to `PO_ERR_INVALID_ARG`, because its
supplied plan is no longer valid for those inputs.

For valid nonoverlapping outputs, rebuild’s output-length pointer becomes zero
on every failure and the destination frame remains untouched. Insufficient
workspace or output capacity returns `PO_ERR_BUFFER_TOO_SMALL`; use the
successful plan's capacities to size both. Scratch workspace contents are
unspecified after a call. These guarantees make a caller-memory transaction
safe to size, retry and commit only after success.

## PO-35 Speech Analysis

`po35_analysis.h` converts finite normalized mono `float` PCM in `[-1,1]`
at 8,000–192,000 Hz into packed 44-byte speech records. It is a one-shot,
approximate LPC analysis model, not the original Bitspeek or PO-35 encoder.
Both the 10-coefficient low bank and 30-coefficient high bank are emitted using
a common bandlimited 24 kHz clock, with the low bank decimated to 8 kHz.

`PO35_ANALYSIS_MODEL_VERSION` is 2. New PCM encodes can produce different
coefficient/gain bytes and rendered audio from model 1. Public types, function
signatures and workspace size are unchanged, as are the 44-byte record layout
and reconstruction synth model 1. Existing records retain their decoding
behavior. The analysis version identifies the host algorithm; it adds no wire
metadata.

Model 2 fits high-bank frames whose full-precision first reflection coefficient
falls outside the decoder's byte-representable range. It keeps that coefficient's
existing boundary byte and performs four forward coordinate sweeps over the
remaining 29 byte codes, minimizing prediction error against the
bandwidth-expanded full-precision filter. Candidate coefficients use the
existing LAR lookup values. A numerically unsafe fit retains the original
bounded coefficients.

The fit preserves pitch, unvoiced and low-bank coefficient fields. Shared gain
is recalibrated after fitting, so a changed gain byte can also change low-bank
audio. Synthetic probes exercise fitting and preservation paths; fitting on
real speech and physical-device playback of newly analyzed records remain
unverified.

Call `po35_analysis_size_for_pcm` before providing output storage. Supported
frame rates are 20, 40, 60 and 80 fps. The required record count is
`ceil(sample_count * fps / sample_rate)`, with a partial final record zero-padded.
The core allows at most `PO35_ANALYSIS_MAX_RECORDS` (65,535) records, matching
the header's 16-bit count. The hosted editor's smaller
[creation limit](../guides/PO35.md#po-35--po-137-speech-replacement) does not
restrict raw parsing or this API.

For example, encode one second of 24 kHz mono PCM at 80 fps:

```c
#include "po35_analysis.h"

po_status_t encode_second(po35_analysis_workspace_t *workspace,
                          const float pcm[24000],
                          uint8_t records[80 * PO35_ANALYSIS_RECORD_BYTES]) {
  size_t required = 0, written = 0;
  po_status_t status = po35_analysis_size_for_pcm(24000, 24000, 80, &required);
  if (status != PO_OK)
    return status;
  return po35_analysis_encode_f32(workspace, pcm, 24000, 24000, 80,
                                   records, required, &written);
}
```

The caller owns the workspace, input and output arrays. The workspace is
currently 49,632 bytes on supported IEEE-754 targets; use
`sizeof(po35_analysis_workspace_t)` and choose storage appropriate to the
application's stack budget. Its members are implementation details and need
no initialization. Workspace, PCM, records and output-length storage must be
disjoint. No allocation or persistent global state is used.

Invalid sample values, rate, fps or duration return `PO_ERR_RANGE`; insufficient
capacity returns `PO_ERR_BUFFER_TOO_SMALL`. Argument and sample validation
precedes record writes. On error, records remain untouched and the output byte
count is zero. Empty PCM requires zero record bytes, but still requires a
workspace; PCM and record pointers may be null when their required size is zero.

Analysis does not normalize input. Shared gain is calibrated to the louder
bank under reconstruction model 1; synthesized transients can still exceed
`[-1,1]`. Applications collect records into speech groups and update their
headers before using the frame builder and stereo transmitter.

## PO-35 Speech Rendering

`po35_synth.h` provides approximate speech reconstruction. Exact hardware voice
characters and effects are not implemented. Use `po35_analysis.h` for PCM input.
The low bank renders at 8 kHz; the high bank renders at 24 kHz. Supported record
rates are 20, 40, 60 and 80 fps.

```c
#include "po35_synth.h"

po_status_t render_speech(const uint8_t *records, size_t record_bytes,
                          uint32_t fps) {
  po35_synth_t synth;
  po35_synth_voice_t voice;
  float block[256];
  size_t written;
  po_status_t status = po35_synth_init(&synth, PO35_SYNTH_BANK_HIGH,
                                     PO35_SYNTH_DEFAULT_SEED);
  if (status == PO_OK)
    status = po35_synth_voice_init(&voice, &synth, records, record_bytes, fps);
  while (status == PO_OK && !po35_synth_voice_done(&voice)) {
    status = po35_synth_voice_render_f32(&voice, block, 256, &written);
    /* Consume written samples, including a finite prefix on numerical error. */
  }
  return status;
}
```

Records are borrowed and must remain immutable while the voice can use them,
including after reset. Record bytes must be a multiple of 44. Use
`po35_synth_samples_for_records` to calculate output length. Frame timing,
oscillator phase, noise and filter state persist across calls; chunked rendering
and reset reproduce the same output within a build.

Output is finite, unnormalized float and may exceed `[-1, 1]`. The renderer
performs no resampling, clipping or normalization. Numerical overflow or
instability returns a latched `PO_ERR_RANGE`; `written` counts only committed
finite samples.
Reset clears the error. `po35_synth_render` wraps the same voice implementation
for one-shot use and writes nothing when output capacity is insufficient.
